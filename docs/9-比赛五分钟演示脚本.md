# 御盾智核比赛五分钟演示脚本

> 冻结版本：Contest Readiness Sprint；主演示模式：`COMPETITION_AUTONOMOUS`。该模式只作用于明确标识的 Synthetic / Mock / Sandbox；真实生产模式仍为 `PRODUCTION_GUARDED`。

## 演示前准备

```bash
make contest-preflight
make dev
```

打开 <http://127.0.0.1:5173>，确认顶部 Model 为 `DETERMINISTIC_TEST`、Stage 可 Reset 为 `IDLE`。若现场已有真实模型配置，可单独展示 live smoke 报告，但不要临时改变稳定 Demo Provider。

## 0:00–0:30 赛题痛点与数据来源

操作：进入 Detection，先指向 Official 与 Synthetic 两个选择框，再选择 `COMPETITION_AUTONOMOUS`。

讲解：

> 御盾智核处理的是 CI 供应链导致 API 凭据泄露与云侧滥用。官方数据提供真实 PCAP 网络攻击证据，但没有 CI Action、云 API Key 或凭据轮换字段，所以我们采用可审计的数据合同：OFFICIAL 是比赛方真实 PCAP；SYNTHETIC 是 CI/云凭据业务链；MOCK 是动态处置沙箱；SYSTEM 是 Agent、Policy、执行、验证和审计对象。四类来源始终独立标识，不伪造官方数据字段。

## 0:30–1:00 Signal + Evidence

操作：Reset，Start Replay；查看 Signal，并打开一条 Evidence。

讲解：

> 系统首先产生风险 Signal，并通过 Evidence locator 回到原始记录。Signal 只是需要调查的风险，不是事实；模型文字也不是 Evidence。

## 1:00–1:45 多智能体调查

操作：进入 Evidence & Investigation，展开任务、允许工具、实际调用和 Finding。

讲解：

> 主 Agent 只负责理解、规划和调度。调查 Agent 只能读取任务授权的 Evidence 和 Tool；它形成 Finding，但不能直接写 ConfirmedFact、改变事件状态或执行动作。智能体可以分析和建议，但不能自己批准、直接执行或把模型判断写成安全事实。

## 1:45–2:20 攻击链与事实

操作：展示 6/6 Confirmed Facts 与确定性 Timeline。

讲解：

> Timeline 按时间与精确关联字段排序，每个节点保留来源和 Evidence 引用。Finding 经过 Fact Validator 校验证据存在、来源合法、关联字段一致后，才能成为 Fact；Official 与 Synthetic 之间没有天然业务 ID，只做明确标注的 Demo 关联。

## 2:20–2:55 Recommendation + Policy

操作：进入 Response & Verification，展示 Recommendation、ActionRequest 和 Policy checks。

讲解：

> Main Agent 只能提出处置建议，Operation Agent 只能生成 ActionRequest。确定性 Policy 检查动作白名单、目标范围、六项事实、三步顺序、请求者、明文秘密和幂等键；LLM 不参与授权。

## 2:55–3:25 两种运行模式

操作：指向顶部 Run Mode 和 `Policy Pre-Authorization` 面板。

讲解：

> 生产 Guarded 模式坚持 Policy → Human Approval → Execution。比赛自治模式只允许 Synthetic/Mock/Sandbox，在显式开关、场景白名单、动作白名单、无生产 Adapter、无任意命令等安全守卫全部通过后，由独立 PolicyPreAuthorization 完成零人工闭环。它不会伪造 ApprovalRecord；本轮 Human Approval Count 为 0。技术上可自治，生产上有边界。

## 3:25–4:05 Controlled Execution

操作：展示三步执行结果与 Before/After Snapshot。

讲解：

> 受控执行器不是 Agent。它只执行冻结的 `FREEZE_OLD_KEY → CREATE_NEW_KEY_VERSION → UPDATE_CI_BINDING`，每一步产生不可变快照和回执；无真实 Key、无 Shell、无生产云写操作。

## 4:05–4:35 Verification

操作：展示 6/6 Recovery Assertions。

讲解：

> 接口 success 不等于事件解决。系统还必须确认旧 Key 失效、恶意调用被拒绝并停止、新版本生效、合法 CI 恢复和高费用资源停止。任一失败都保持 ROTATED 并 Observe → Replan，绝不强制 CLOSED。

## 4:35–5:00 Audit + 三重任务总结

操作：进入 Audit & Trace，展示 Hash Chain VALID 和 Reasoning Trace。

讲解：

> 这里展示的不是模型隐藏思维，而是结构化、证据驱动、可审计推理轨迹：Observation → Evidence → Task → Finding → Fact → Decision → Action → Observation → Replan/Close。基础任务由场景化多 Agent 闭环证明；进阶任务由 Tool Registry、ACL 和行动工具扩展证明；挑战任务由 Main SuperAgent、可审计轨迹和零人工 Sandbox 闭环证明。深信服真实接口尚待企业方提供，我们不会把本地 Adapter 或 Mock 宣称为已接入。

## 现场降级话术

- 公网不可用：`DETERMINISTIC_TEST + Official offline PCAP + Synthetic + Mock` 仍可完整演示。
- DeepSeek/Qwen 不可用：明确显示 Provider unavailable / `BLOCKED_CONFIG`，不无限加载，不冒充真实调用。
- Autonomous 异常：切回 `PRODUCTION_GUARDED`，人工批准路径经过独立回归，不受自治分支影响。
- Verification 失败：主动展示 ROTATED + REPLAN，说明系统 Fail Safe，而不是临时改数据制造 CLOSED。

## 真实耗时基线

2026-08-10 开发机自动化实测：后端冷导入约 0.79 秒，前端加载约 0.29 秒，Reset 约 0.10 秒，Guarded Replay 到审批约 0.42 秒，审批恢复约 0.23 秒，含 10 张证据截图的浏览器自动操作完整闭环约 2.26 秒；三轮 Autonomous 后端闭环约 0.29–0.33 秒/轮。以上是本机回归耗时，不是生产 SLA；五分钟主要用于解释证据和安全边界。
