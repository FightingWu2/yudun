# 御盾智核 P0 系统验收与演示说明

> 验收范围：DEV-001～DEV-030；运行日期：2026-08-10。

## 1. 当前结论

P0 Golden Path 已形成可启动、可在浏览器演示、可连续重放、可自动验收的模块化单体。当前演示使用明确标识的 Official 离线网络证据、Synthetic 凭据攻击链、Mock/Sandbox 动态状态和 System 审计对象；实际模型 Provider 为 `DETERMINISTIC_TEST`。

## 2. 启动与验收

```bash
make install
make install-frontend
make dev
```

访问 <http://127.0.0.1:5173>。重置已运行服务使用 `make demo-reset`；完整静态/后端检查使用 `make check`；三轮浏览器验收使用 `make demo-e2e`；真实模型现实性检查使用 `make live-model-smoke`。

## 3. 本地角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| ADMIN | 选择 allowlist 数据、Reset、Start Replay、查看 | 不能直接执行、伪造 Policy 或 Verification |
| ANALYST | 查看 Incident、Evidence、Agent、Timeline、Action | 不能审批或执行 |
| APPROVER | 查看 Request/Policy/Digest，批准或拒绝 | 不能修改 Request 或直接执行 |
| AUDITOR | 查看脱敏 Evidence 索引、Audit、Trace、执行与验证 | 不能修改历史记录 |

这只是本地 Demo 权限隔离，不是生产 IAM/SSO。

## 4. Demo 场景与来源

- `OFFICIAL`：比赛官方 PCAP/PCAP-NG，仅证明抓包中真实存在的网络事实，通过 capture/packet locator 回查。
- `SYNTHETIC`：`scenario_api_key_compromise_v1`，表达 CI Action 变化、Runner 访问凭据、凭据暴露、云 API 异常、敏感读取和高费用资源创建。
- `MOCK`：审批后的凭据冻结、新版本、CI 绑定、攻击状态、资源状态与恢复回读；不是生产云。
- `SYSTEM`：策略、审批、执行、验证、状态迁移和审计记录。

Official 与 Synthetic 不宣称天然因果关系；界面以不同 Badge 展示。

## 5. 五分钟 Golden Path

1. Detection 页由 ADMIN Reset，选择 Official 样本和 Synthetic 场景后 Start Replay。
2. 查看 Signal、Evidence 与 Incident；强调 Signal 不是 Fact。
3. Investigation 页查看受限 Agent Task、允许/拒绝 Tool、实际调用、Finding、六个 Fact 与确定性 Timeline。
4. Response 页查看 Recommendation 和八项 Policy；此时 Mock 未变化。
5. 切换 APPROVER，核对 Request digest 后批准；系统恢复同一 LangGraph thread。
6. 查看 `FREEZE_OLD_KEY → CREATE_NEW_KEY_VERSION → UPDATE_CI_BINDING` 三步真实 Mock 状态变化。
7. 查看六项恢复断言及其 Evidence；只有 6/6 才能 VERIFIED。
8. Audit 页确认结构化 Reasoning Trace、Hash Chain VALID 与 Incident CLOSED。

## 6. 页面映射

| 工作区 | 用户实际看到什么 |
|---|---|
| Detection & Incident | 数据来源、重放控制、Incident 状态、Signal、Evidence 索引与安全 locator |
| Evidence & Investigation | Agent Task/Result/Finding、Tool ACL/实际调用、ConfirmedFact、攻击时间线 |
| Response & Verification | Recommendation、Policy checks、Digest、审批、Mock 前态、Execution、六项 Verification |
| Audit & Trace | Audit chain 完整性、结构化 Observation/Evidence/Task/Finding/Fact/Decision/Action/Replan |

## 7. 自动验收

`make demo-e2e` 使用真实 Chromium 页面和 API，连续三次执行完整闭环，要求每轮新 Runtime/Incident、6 Facts、3 Execution steps、6/6 Verification、Audit VALID、CLOSED，且不混入上一轮对象。报告写入 `artifacts/golden_path_product_report.json`。

安全失败回归覆盖：无证据提升、Agent 越权执行、Policy 越界、人工拒绝、Request 篡改、重复 Resume/Execute、验证失败、模型失败、Prompt Injection、Audit 损坏、秘密泄露、来源误表示。失败均 Fail Safe。

## 8. Provider 与运行模式

- `DETERMINISTIC_TEST`：已实现并用于稳定的单元、集成和 Demo 回归；不代表真实大模型能力。
- DeepSeek：`LIVE VALIDATION PENDING`，缺完整 `DEEPSEEK_API_KEY/BASE_URL/MODEL` 配置。
- Qwen：`LIVE VALIDATION PENDING`，缺完整 `QWEN_API_KEY/BASE_URL/MODEL` 配置或本地服务。
- `PRODUCTION_GUARDED`：已实现（Policy → Human Approval → Controlled Mock Execution）。
- `COMPETITION_AUTONOMOUS`：已实现且仅限 Synthetic/Mock/Sandbox；使用独立 PolicyPreAuthorization，不伪造人工 ApprovalRecord。

## 9. 外部依赖与已知限制

- 深信服 AI 安全平台：`PENDING EXTERNAL INTERFACE`。
- Security Knowledge RAG、BGE-M3、SecureBERT 增益实验：未实现。
- 当前没有真实云生产写操作、企业 IAM、多租户或微服务部署。
- Official 数据为离线重放，不是实时生产流量。
- 性能报告是本机 Demo 回归耗时，不是生产 SLA。
- 赛场预检已在当前目标设备完成：阻断外部网络后两条路径可运行，1280×720 与 1440×900 浏览器验收通过；换用正式比赛设备时仍应重新执行 `make contest-preflight`。
