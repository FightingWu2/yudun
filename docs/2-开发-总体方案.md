# 安全多智能体系统开发文档

## 1. 文档范围

本文档记录已经确认的产品场景、攻击链、总体架构和开发边界。

本文档已经记录目前确认的子代理命名、总体职责、调度方式和模型配置。各子代理的具体网安探针、检测规则、证据关联细节和操作参数仍暂不确定，后续结合开发和演示需要逐步补充。

## 2. 产品定位

本系统面向云服务商安全运营团队，用于处理租户 API 凭据泄露后的异常使用、影响分析和安全响应。

系统采用主代理统筹、多个子代理分工协作的方式。多代理的核心价值不是让模型互相聊天，而是按职责、数据和操作权限进行隔离，降低单个代理失误或被攻击后的影响范围。

产品的通用定位是：

> 面向云服务商的安全事件监测、调查、溯源、操作执行和审计汇报多智能体协作系统。

本次比赛 Demo 聚焦一个具体场景：

> 第三方 CI Action 被篡改，导致租户 CI/CD 环境中的 API Key 泄露；攻击者使用该 Key 调用云 API，读取租户敏感数据并创建高费用云资源；系统发现异常后，由主代理调度多个子代理完成调查、溯源、响应和审计。

## 3. 问题依据

API 凭据暴露是云安全中的常见问题，但“凭据暴露”不等于“已经发生攻击成功”。系统需要区分：

- 凭据是否可能暴露
- 凭据是否仍然有效
- 是否出现异常调用
- 是否读取了敏感数据
- 是否创建了高费用资源
- 是否已经造成确定性损失

可使用的公开依据：

- GitGuardian：公开代码和容器镜像中存在大量硬编码秘密，包括 API Key 和 Token。URL：https://www.gitguardian.com/state-of-secrets-sprawl-report-2025
- Verizon DBIR：被盗或受损凭据长期是数据泄露的重要攻击路径。URL：https://www.verizon.com/business/resources/Te3/reports/2024-dbir-data-breach-investigations-report.pdf
- GitHub Secret Scanning：公开凭据可被检测，并可联动凭据提供方进行撤销。URL：https://docs.github.com/en/code-security/secret-scanning/introduction/about-secret-scanning
- Codecov：被篡改的 CI 上传器可以读取 CI 环境变量并外传。URL：https://about.codecov.io/security-update/
- CircleCI：安全事件后要求用户轮换 Project Token、环境变量、SSH Key 等凭据。URL：https://circleci.com/blog/january-4-2023-security-alert/
- AWS IAM：怀疑 Access Key 泄露后，应停用、轮换并检查使用记录。URL：https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html

推荐对外表述：

> API 凭据暴露是云服务中的常见风险，公开代码、容器镜像、CI/CD 环境和第三方自动化组件都可能成为泄露渠道。泄露不等于已经被利用，但有效凭据一旦被异常调用，可能导致源码访问、数据读取、云资源操作、供应链发布或费用消耗。

## 4. 服务对象和数据入口

### 4.1 服务对象

系统服务对象是云服务商安全运营团队。

云服务商通过安全连接器接入租户授权的 CI 安全事件、云 API 调用日志、认证日志、资源操作日志和凭据状态信息。系统不假设云服务商可以无条件读取租户 CI 内部数据，也不直接读取租户明文 API Key。

### 4.2 数据入口

首个 Demo 使用以下数据入口：

- 租户 CI 安全连接器：提供第三方 Action 版本、Digest、权限和 Secret 访问事件
- 云 API 审计日志：提供 API Key 的调用时间、来源、接口、资源和结果
- 流量与认证事件：提供来源 IP、地区、Runner、设备、认证结果和调用频率
- 资源操作事件：提供数据读取、资源创建、权限变化和费用相关事件
- 凭据状态服务：提供凭据是否有效、是否冻结、是否已轮换等状态

## 5. 比赛 Demo 攻击场景

### 5.1 攻击链

```text
第三方 CI Action 被篡改
    -> CI Runner 读取环境变量中的 API Key
    -> API Key 被外传并被攻击者使用
    -> 攻击者从新来源调用云 API
    -> 读取租户敏感数据
    -> 创建高费用云资源
    -> 系统产生安全事件
    -> 主代理调度子代理调查、溯源和响应
```

### 5.2 事件起点

事件可以由两个信号共同触发：

1. CI 安全连接器发现第三方 Action 的版本、Digest 或权限发生异常变化。
2. 云侧监测发现相关 API Key 出现异常调用。

本次 Demo 将二者关联起来，展示：

```text
CI 组件异常
    +
API Key 异常调用
    -> 凭据泄露与滥用的高风险事件
```

### 5.3 API Key 异常调用示例

“异常调用”不是单一规则，而是多个可解释信号的组合。Demo 可以使用以下信号：

- 新来源 IP、地区、Runner 或设备调用
- 调用时间偏离租户历史基线
- 短时间内调用频率明显升高
- 首次访问租户敏感数据接口
- 首次创建高费用或大规模资源
- 调用链紧跟 CI Action 变化或 Secret 访问事件
- 调用目标、接口组合或资源范围偏离该 Key 的历史用途
- 失败重试、枚举式访问或异常权限边界探测

这些信号由静态规则、统计基线和模型分析共同处理。模型用于分类、排序和解释，不能单独决定冻结、轮换或放行。

## 6. 总体架构

```text
租户 CI / 云 API / 认证 / 流量 / 资源 / 凭据状态
                         |
                    安全连接器
                         |
                事件总线与审计存储
                         |
                   静默监测子代理
                         |
                       主代理
          用户交互、任务理解、流程编排、结果汇总
             /          |          |          \
     事件调查子代理  攻击溯源子代理  操作执行子代理  审计汇报子代理
                         |
          确定性策略引擎、审批、受控执行接口
                         |
          冻结凭据、轮换凭据、验证恢复、留存证据
```

主代理调度层使用 `LangGraph` 实现。主代理根据事件状态和子代理返回结果决定下一步调用，可以根据任务依赖关系选择串行或并行执行。子代理不直接互相调度，所有协作结果先写入事件状态中枢，再由主代理读取并继续编排。

本系统暂不采用 `pi` 作为底层调度框架。`pi` 更适合轻量级智能体循环和工具调用；本项目当前更需要明确的状态、节点、条件调度、暂停和恢复能力。具体代码实现和前端演示仍属于后续开发事项。

## 7. 主代理和子代理的总体边界

### 7.1 主代理

主代理负责：

- 接收安全运营人员指令和系统告警
- 理解事件目标和当前状态
- 按需调度子代理
- 为子代理分配最小必要任务
- 汇总结构化结果
- 推进事件流程
- 向用户解释证据、风险和处置进度

主代理不应：

- 直接读取明文 API Key
- 直接访问未经授权的原始数据源
- 直接执行冻结、轮换和资源操作
- 绕过策略引擎或人工审批

### 7.2 子代理架构原则

子代理的划分同时服务于两件事：

1. **职责分工**：每个子代理处理一个相对清晰的安全工作面。
2. **权限与风险隔离**：每个子代理只获得完成任务所需的数据和工具权限。

因此，多智能体不是简单地把一个大任务拆成多个聊天窗口，而是将读取权限、分析权限和操作权限分开。即使某个子代理判断错误或受到输入污染，也限制其可见数据和可执行动作。

当前已经确认以下子代理名称和总体职责：

- **静默监测子代理**：后台持续运行，调用必要的监测探针或其他只读工具接收安全事件；由小模型判断风险信号，发现风险后向主代理汇报结构化告警。不负责完整调查、攻击溯源、冻结、轮换或恢复。
- **事件调查子代理**：围绕告警查询相关证据，确认事件事实、敏感数据读取、高费用资源创建等影响。默认只读，不能访问明文凭据。
- **攻击溯源子代理**：还原攻击来源、身份、时间线，以及第三方自动化组件、运行环境和 API Key 使用之间的关系。默认只读，不能执行处置动作，也不能仅凭模型结果认定攻击者或组织。
- **操作执行子代理**：把冻结、轮换、恢复和验证等处置内容转换为结构化操作申请，并通过受控接口提交。不能自行决定是否执行，不能直接改变权限或执行高风险动作。
- **审计汇报子代理**：整理脱敏证据、子代理结论、动作记录、审批信息和最终事件报告。只能生成报告和留痕，不能删除或修改审计证据，不能执行资源操作。

子代理本身使用小模型，但小模型只负责各自职责范围内的判断、提取、排序、解释或操作申请生成。小模型不是授权器，不能替代确定性策略、审批和受控执行接口。

### 7.3 主代理调度机制

主代理负责统一调度，不要求固定的线性流程：

- 主代理接收安全运营人员指令或静默监测子代理产生的结构化告警。
- 主代理根据事件类型、当前状态和已有证据，决定调用哪个子代理。
- 任务之间互不依赖时，可以并行调用多个只读子代理；存在依赖时，按结果串行调用。
- 主代理可以根据结果补充条件后再次调用同一个子代理，但每次调用必须有新的任务目标。
- 连续调用没有产生新证据时，应停止调度并报告证据不足或不确定。
- 子代理之间不能直接通信，也不能直接调用其他子代理。
- 主代理只向子代理传递本次任务需要的事件摘要、证据引用、任务目标和返回格式，不传递完整历史对话、无关上下文或明文凭据。

子代理统一返回结构化结果，至少包括：

- 任务是否完成
- 当前调查结论
- 证据摘要和证据引用
- 风险等级或置信度
- 未确定事项
- 建议的下一步
- 是否建议继续调用其他子代理
- 是否涉及需要审批的操作

子代理返回的是本次任务结果，不直接决定整个事件是否结束；主代理根据结果决定后续调度。

### 7.4 事件状态中枢

事件状态中枢是多智能体协作的共享状态模块，采用结构化状态文本保存事件的最新状态和必要证据。它不是让所有子代理共享完整对话记忆，而是让各子代理围绕同一份结构化事件信息协作，减少主代理重复转述造成的信息衰减。

事件状态中枢至少保存：

- 事件基本信息
- 当前事件状态
- 已确认的证据摘要和证据位置
- 各子代理的调查结论和置信度
- 未解决问题
- 待执行的操作申请
- 主代理调度记录
- 人工审批和审计记录

权限规则：

- 子代理只能在授权范围内追加本次任务的证据摘要和结构化结果。
- 已写入的证据和结果不能被其他子代理覆盖或无痕删除。
- 主代理可以修改或删除错误内容，用于纠正子代理错误或解除状态阻塞。
- 人工拥有最高修改权限，可以修改状态或内容，但必须填写修改原因。
- 主代理和人工的修改必须记录修改前内容、修改后内容、修改原因和修改者。
- 被删除的内容不参与当前判断，但仍保留在审计记录中。
- 事件状态中枢不保存明文 API Key，不保存无关的完整对话。

事件状态变更必须有充分证据和置信度。主代理提出状态变更，事件管理器进行二次校验后写入；具体证据数量、置信度阈值和人工强制修改的详细规则暂留空，后续再确定。

## 8. 权限和风险隔离原则

```text
主代理提出调度计划
    -> 子代理在各自权限范围内执行
    -> 返回结构化结果
    -> 策略引擎校验高风险动作
    -> 审批或受控执行
```

基本限制：

- 原始 API Key 不进入模型上下文和普通日志
- 子代理之间通过结构化事件和证据引用通信
- 监测、调查、溯源和审计子代理默认只读
- 操作执行子代理不能自行决定是否执行高风险动作
- 冻结、轮换和资源操作必须经过确定性策略校验
- 生产环境高风险动作需要人工审批
- 所有查询、判断、调度和执行都需要留存审计记录
- 模型失败、超时或知识检索失败时不得自动放行高风险动作
- 每个子代理的工具权限预先固定，主代理只能在该范围内分配任务，不能临时扩大权限
- 权限不足时，子代理应返回“无法完成，缺少授权”，不能自行绕过限制
- 操作执行子代理只能提交操作申请和查询受控执行结果，不能直接执行冻结、轮换或恢复
- 子代理可以建议继续调查或调用某类子代理，但最终由主代理决定是否调度

各子代理的具体工具清单暂不写死。当前只保留“静默监测子代理可调用必要的监测探针或只读工具，由小模型判断并向主代理汇报”的设计原则，具体网安探针、字段和检测规则后续确定。

## 9. Demo 闭环

```text
1. 监测子代理静默接收 CI、认证、云 API 和资源事件
2. 发现 CI Action 变化与 API Key 异常调用的组合信号
3. 生成结构化高风险告警
4. 主代理接收告警并请求事件调查
5. 事件调查子代理确认敏感数据读取和高费用资源创建
6. 攻击溯源子代理关联 CI Action、Runner、API Key 和攻击来源
7. 主代理形成处置计划
8. 操作执行子代理提交冻结和轮换请求
9. 策略引擎与审批流程通过后执行受控操作
10. 验证旧 Key 失效、新 Key 可用、合法业务恢复
11. 审计汇报子代理生成事件报告
```

事件创建规则：

- 任一高风险信号出现时，立即创建安全事件，初始状态为“已发现”。
- 第三方自动化组件异常和 API Key 异常调用作为两条独立证据写入同一安全事件。
- 两条证据能够关联时，事件升级为高风险并进入调查流程。
- 本次 Demo 中两条证据同时出现，直接展示完整事件闭环。
- 两条证据的详细关联条件暂不确定，后续再补充。

五分钟演示是待开发项目，当前尚未确认 `LangGraph` 的调度配置、事件状态中枢和前端是否能够完整呈现：

- 主代理收到告警后的任务分配
- 子代理串行或并行执行
- 事件状态中枢的结构化状态变化
- 证据摘要和置信度的持续追加
- 操作申请、策略校验和人工审批
- 最终审计汇报

后续需要用一个可运行的最小前端，把上述过程压缩成五分钟内可以看懂和复现的演示流程。前端只展示结构化状态、证据、调度、审批和结果，不展示模型隐藏推理过程。

最终事件状态可以采用：

```text
NEW
-> DETECTED
-> INVESTIGATING
-> ATTRIBUTED
-> CONTAINED
-> ROTATED
-> VERIFIED
-> CLOSED
```

## 10. Demo 与通用产品的边界

产品层面保留通用名称和接口：

- 静默监测子代理可以监测不同类型的安全事件
- 事件调查子代理可以查询不同数据源
- 攻击溯源子代理可以处理不同攻击链
- 操作执行子代理可以对接不同受控操作
- 审计汇报子代理可以输出不同事件报告

本次 Demo 只验证一条具体链路：

> 第三方 CI Action 篡改 -> API Key 泄露 -> 异常云 API 调用 -> 敏感数据读取与高费用资源创建 -> 多子代理协作响应。

不能把 Demo 的单一实现描述成已经覆盖所有凭据泄露、所有云平台或所有攻击类型。

## 11. 开发边界

本阶段必须保留：

- 一个云平台适配范围
- 一个租户事件模型
- 一类 API Key
- 一条 CI Action 篡改到 API 滥用的攻击链
- 一个静默监测子代理
- 主代理调度和用户交互
- 调查、溯源、操作执行、审计汇报的子代理接口
- 确定性策略、审批和审计
- Mock 或沙箱化的冻结、轮换和恢复验证

本阶段不做：

- 真实生产凭据
- 任意 Shell 执行
- 未授权网络访问
- 自动修改真实生产资源
- 完整 SIEM、EDR、IAM 或 CWPP
- 所有 API 泄露来源和所有攻击类型
- 多个无边界的通用 Agent 自由协作
- 让大模型直接决定权限或执行高风险动作

### 11.1 底层框架和模型配置

#### 调度框架

- 使用 `LangGraph` 作为多智能体系统的底层调度框架。
- 主代理负责图中的流程编排和条件调度。
- 子代理作为受限调度节点，不能直接互相调度。
- 事件状态中枢作为业务层共享状态，不把框架自带的会话记忆直接当作安全事实来源。
- 具体图结构、检查点保存、暂停恢复和前端连接方式属于待开发内容。

#### 模型配置

采用“三类本地小模型加一个接口大模型”的共享模型池，而不是给每个子代理单独部署一个模型。这样可以降低生产端显存和运维成本，也方便后续替换模型。

本地小模型配置：

- 静默监测子代理：使用 `SecureBERT2.0`，用于安全事件分类、凭据字段识别、异常类型识别和告警初筛。该模型的安全领域能力主要面向英文安全语料，中文告警效果需要后续验证。
- 事件调查子代理：使用 `Qwen3-4B`，用于读取结构化证据、整理事件事实、生成调查结论和提出待查问题。
- 攻击溯源子代理：使用 `BGE-M3` 和 `bge-reranker-v2-m3` 进行证据检索、相似事件召回和时间线排序，必要时共享 `Qwen3-4B` 生成关系解释。模型输出不能单独用于攻击者归因或报复行动。
- 操作执行子代理：共享 `Qwen3-4B`，只负责把处置建议转换为固定格式的操作申请，不能决定操作是否允许，也不能直接执行。
- 审计汇报子代理：共享 `Qwen3-4B`，用于汇总证据、动作记录、审批信息和未确认事项，生成结构化事件报告。

主代理配置：

- 使用接口调用的大模型 `deepseek-v4-flash`，负责理解用户指令和安全告警、选择子代理、安排串行或并行调用、读取事件状态中枢、汇总结果和解释当前进度。
- 复杂事件或正式汇报是否切换到 `deepseek-v4-pro`，后续根据成本和效果再决定。
- 主代理不直接读取明文凭据，不直接执行高风险动作。

模型边界：

- 小模型可以负责分类、抽取、排序、敏感信息识别、异常分析、证据解释和操作申请生成。
- 模型不能成为授权器，不能直接决定冻结、轮换、恢复、创建资源或改变权限。
- 确定性策略和人工审批负责最终放行高风险操作。
- 安全微调先作为后续优化方向，不在当前文档中写死训练数据、训练方法和最终模型版本。
