# 御盾智核 前端数据与状态字典

> 本文档是 `docs/12-前端开发交接说明.md` 的配套数据字典。它回答三个问题：
> 1. 前端从后端拿到的每个对象长什么样、字段是什么意思。
> 2. 状态机如何流转、谁推进了状态。
> 3. 数据从哪个 API / SSE 事件来。
>
> 数据契约的权威来源：`frontend/src/api.ts`（TypeScript 类型）与 `backend/app/schemas/*.py`（Pydantic）。字段名与语义以这两处为准；本文档是它们的可读版。

---

## 1. 前端数据流总览

```
┌───────────────────────────────────────────────────────────────────────┐
│  App.tsx 顶层状态（纯前端本地，不持久化）                                  │
│  role / workspace / sources / runtime / bundle / captureId / scenarioId │
│  runMode / selectedEvidence / busy / error                              │
└───────┬───────────────────────────────────────────────────────────────┘
        │ 启动时
        ▼
GET /replay/sources ───────────► ReplaySources（Official 样本 / Synthetic 场景 / run_modes）
GET /runtime/status ───────────► RuntimeStatus（run_id / incident_id / stage / provider…）
        │ 若有 incident_id
        ▼
GET /incidents/{id}/bundle ────► IncidentBundle（★ 前端唯一数据视图）
        │ SSE：incident.updated / approval.* / execution.* / verification.* / incident.closed…
        ▼
refresh() 重新拉 /runtime/status + /incidents/{id}/bundle
```

- **前端只有一个数据视图 `IncidentBundle`**：所有工作区（Detection/Investigation/Response/Audit）都从同一个 bundle 取数。
- 业务状态只有三个**写操作**：`POST /replay/reset`（ADMIN）、`POST /replay/start`（ADMIN）、`POST /approvals`（APPROVER）。除此之外前端全部只读。
- `Evidence` 详情是唯一按需拉取的子资源：`GET /evidence/{id}`（打开 drawer 时）。

## 2. 对象字典

> 每条给出：对象名 / TypeScript 接口（在 `frontend/src/api.ts`）/ 后端来源 / 关键字段。`★` 表示 UI 直接依赖。

### 2.1 RuntimeStatus — 运行状态
| 字段 | 类型 | 含义 |
|---|---|---|
| `run_id` | string\|null | 本轮运行 ID（每轮全新） |
| `incident_id` | string\|null | 当前 Incident ID；null = 尚未重放 |
| `stage` | string | 工作流当前阶段：`IDLE` / `WAITING_APPROVAL` / `CLOSED` / `MANUAL_REQUIRED` / `POLICY_DENIED` / …（见 4.4） |
| `run_mode` | string | `PRODUCTION_GUARDED` / `COMPETITION_AUTONOMOUS` |
| `model_provider` | string | 当前恒为 `DETERMINISTIC_TEST`（见 docs/12 §14） |
| `competition_autonomous` | string | `IMPLEMENTED_ENABLED` / `IMPLEMENTED_DISABLED` |
| `autonomous_enabled` | boolean | 是否开启 Autonomous 沙箱 |
| `node_timings_ms` | Record<string, number[]> | 各 LangGraph 节点耗时（演示报告用） |
| `stop_reason` | string\|null | 停止原因（`CLOSED` / `HUMAN_REJECTED` / `POLICY_DENIED` / `MODEL_UNAVAILABLE` / `VERIFICATION_FAILED_REPLAN` / …） |

来源：`GET /runtime/status`，`backend/app/application/demo.py` → `DemoRuntime.status()`。

### 2.2 ReplaySources / ReplaySource — 可重放来源
| 字段 | 类型 | 含义 |
|---|---|---|
| `official[]` | ReplaySource[] | 官方 NTA 样本（`source_type: "OFFICIAL"`，含 `capture_id`/`display_name`/`packet_count`/`format`） |
| `synthetic[]` | ReplaySource[] | Synthetic 场景（`source_type: "SYNTHETIC"`，含 `scenario_id`/`display_name`） |
| `run_modes[]` | {run_mode, enabled, safety_label}[] | 可选运行模式；`enabled:false` 时前端应禁用该选项 |

来源：`GET /replay/sources`。Synthetic 当前固定只有一个场景 `scenario_api_key_compromise_v1`（`backend/app/synthetic/scenario.py`）。

### 2.3 Incident — 安全事件
| 字段 | 类型 | 含义 |
|---|---|---|
| `incident_id` | string | 格式 `inc_<ULID>` |
| `title` / `summary` | string | 标题与摘要 |
| `status` | string | `NEW→DETECTED→INVESTIGATING→ATTRIBUTED→CONTAINED→ROTATED→VERIFIED→CLOSED`（见 4.1） |
| `automation_state` | string | `ACTIVE`/`AWAITING_APPROVAL`/`MANUAL_REQUIRED`/`PAUSED`/`FAILED_SAFE`/`COMPLETED` |
| `severity` | string | `INFO`/`LOW`/`MEDIUM`/`HIGH`/`CRITICAL`（demo 为 `CRITICAL`） |
| `signal_refs` / `fact_refs` / `task_refs` / `pending_action_refs` | string[] | 关联对象 ID |
| `version` | number | 乐观锁版本（`EventStateManager` 写时校验） |
| `opened_at` / `updated_at` | string | UTC RFC3339 |
| `current_blocker` / `next_expected_stage` | string\|null | 仅读视图补充：阻塞说明 / 下一状态 |

来源：`GET /incidents/{id}`；前端通常经 `bundle.incident`。

### 2.4 Evidence — 证据 ★
| 字段 | 类型 | 含义 |
|---|---|---|
| `evidence_id` | string | 格式 `evd_<ULID>` |

| `sensitivity` | string | `PUBLIC`/`INTERNAL`/`SENSITIVE`/`RESTRICTED`/`SECRET`（SECRET 拒绝返回） |

来源：`bundle.evidence`（Synthetic/Mock/System 证据）、`bundle.official_evidence`（官方验证证据）、`GET /evidence/{id}`（详情）。

## 4. 状态机

### 4.1 IncidentStatus 流转（严格单步推进）
```
NEW → DETECTED → INVESTIGATING → ATTRIBUTED → CONTAINED → ROTATED → VERIFIED → CLOSED
```
推进守卫（`backend/app/services/state.py` `EventStateManager._guard`）：

| 迁移 | 前置条件 |
|---|---|
| → DETECTED | ≥1 个证据支撑的 Signal |
| → INVESTIGATING | ≥1 个被授权任务 |
| → ATTRIBUTED | **全部 6 个** Golden Path Fact |
| → CONTAINED | 已批准遏制 + 状态回读（`FREEZE_OLD_KEY` 完成） |
| → ROTATED | 新凭据与 CI 绑定验证（`UPDATE_CI_BINDING` 完成） |
| → VERIFIED | 6/6 恢复断言通过 |
| → CLOSED | 审计完整 + 报告生成 + 无遗留高危动作（审计链 VALID） |

任何非单步迁移 → 审计 `STATE_TRANSITION_DENIED` + `InvalidStateTransitionError`(409)。

### 4.2 ActionRequestStatus（`backend/app/schemas/action.py`）
```
DRAFT → POLICY_PENDING → POLICY_DENIED | APPROVAL_PENDING → APPROVED | REJECTED → EXECUTING → EXECUTED | FAILED
```

### 4.3 ExecutionStatus / VerificationNextStep
- `ExecutionStatus`: `PENDING → RUNNING → SUCCEEDED | PARTIAL | FAILED | DENIED | UNKNOWN`
- `VerificationNextStep`: `CLOSE`（PASSED） / `REPLAN`（FAILED） / `MANUAL_REVIEW`
- Verification 与 Incident 的关系：`PASSED` 且当前 `ROTATED` → `VERIFIED`；`FAILED` → 保持 `ROTATED`，走 `replan_or_manual`。

### 4.4 Demo 运行时 stage（`runtime.stage`，`DemoRuntime.status()`）
| stage | 出现时机 |
|---|---|
| `IDLE` | 尚未重放 / 已 reset |
| `WAITING_APPROVAL` | Guarded 在 `wait_for_approval` 中断，等人类审批 |
| `CLOSED` | 成功闭环 |
| `MANUAL_REQUIRED` | `MODEL_UNAVAILABLE` / `SCHEMA_INVALID` |
| `POLICY_DENIED` | Policy 拒绝 |
| `HUMAN_REJECTED` | 审批人拒绝 |
| `AUTONOMOUS_PREAUTHORIZATION_DENIED` | 自治预授权拒绝 |
| `VERIFICATION_FAILED_REPLAN` | 验证失败进入 Replan |

| `asc_` | AssociationRecord | `aud_` | AuditRecord |

校验失败 → `SCHEMA_INVALID`(422)。前端做展示时不要造出不带合法前缀的假 ID。

## 9. 关键数据不变量（前端开发必须遵守）

1. `bundle.incident.status` 与 `bundle.runtime.stage` 均由后端决定；前端只展示。
2. 批准前 `bundle.mock_state` 必须显示**前态**（旧 key `ACTIVE`）；批准后执行完成显示**后态**（旧 key `FROZEN`）。
3. `bundle.verification` 只有 6/6 才 `CLOSED`；`next_step === "REPLAN"` 时 Incident 保持 `ROTATED`。
4. `bundle.audit.chain_valid` 为 false 时不能显示 CLOSED。
5. `bundle.facts.length` 在 `ATTRIBUTED` 及之后固定为 6。
6. `bundle.actions.executions` 在批准前必须为 0 条；批准后恰好 1 条、3 个 `operation_results`。
7. Autonomous 模式下 `bundle.actions.approvals.length` 必须为 0。
