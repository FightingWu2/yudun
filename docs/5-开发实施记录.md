## 设计偏差 / 待确认问题

### DESIGN-ISSUE-001：统一枚举与后续 Schema 示例值不一致（RESOLVED）

- 现象：`4-开发-详细设计.md` 第 3.3 节统一枚举与第 4.7、4.10、4.12、4.14 节示例在 AutomationState、TaskStatus、EvidenceSensitivity、ExecutionStatus、VerificationAssertionType 等值名上存在差异。
- 最终处理：第 3.3 节成为唯一规范枚举源；`SECRET`、`UNKNOWN` 作为安全必需值保留；`SupportType` 与 `FactSupportType` 按不同语义保留。冲突示例已同步修正并增加 Enum Compatibility Decision。
- 迁移结论：尚无包含冲突旧值的业务数据，SQLite 列为字符串且无数据库枚举约束，不需要数据迁移。未来历史导入必须显式版本迁移，禁止静默别名。

### DESIGN-ISSUE-002：部分对象没有冻结专用 ID 前缀（RESOLVED / FROZEN）

- 现象：详细设计 ID 表没有 assessment、HTTPEvent、DNSEvent 专用前缀。
- 最终处理：HTTPEvent/DNSEvent 是 RawEvent 的协议化视图，固定继续使用 `raw_`；RiskAssessment 是独立事件级对象，固定使用 `rsk_`。ID Factory、Schema、fixture、测试和第 3.4 节已同步。
- 影响：对象类型由 Schema/ORM 类型区分，不依靠增加形式化前缀；不存在历史数据迁移。
